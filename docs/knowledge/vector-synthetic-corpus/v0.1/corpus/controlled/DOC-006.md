# DOC-006 — Kubernetes startup probes for slow initialization

Use a Kubernetes startup probe when an application legitimately needs a long initialization period. While the startup probe has not succeeded, Kubernetes does not apply the liveness or readiness probes. This prevents a slow bootstrap from being killed as if it had become unhealthy.

Examples include loading a local embedding model, restoring a vector index, or replaying required metadata. Make the startup probe budget explicit and keep readiness focused on whether the service can accept requests after startup.
