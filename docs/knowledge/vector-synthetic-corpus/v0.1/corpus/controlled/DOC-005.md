# DOC-005 — Kubernetes liveness and readiness

A Kubernetes liveness probe answers whether a running container should be restarted. A readiness probe answers whether the application can receive service traffic. A process may be alive while it is not ready because it is warming a cache, opening a database connection, or loading a search index.

Do not use liveness failure to model ordinary startup delay. Repeated liveness failure can restart a healthy-but-slow application before it becomes ready. Route traffic only after readiness succeeds.
