# DOC-015 — Java virtual threads and blocking I/O

Java virtual threads make it practical to represent many blocking I/O tasks as ordinary sequential code. A virtual thread is not a faster CPU core: CPU-bound work still competes for processor time. Avoid holding a synchronized monitor across a long blocking operation because it can pin a carrier thread.

For a retrieval service, virtual threads can simplify concurrent outbound calls or independent document reads. Measure queueing, latency, and failure behavior rather than assuming that higher concurrency improves ranking quality.
