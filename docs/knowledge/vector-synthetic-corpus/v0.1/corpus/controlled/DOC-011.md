# DOC-011 — HTTP idempotency for retries

An HTTP operation is idempotent when repeating the same request has the same intended effect as issuing it once. `GET`, `PUT`, and `DELETE` are conventionally idempotent; a `POST` is not necessarily idempotent.

For a retried create operation, accept an idempotency key and store the completed outcome by that key. A timeout can then be retried without silently creating a second resource. Network retry policy must distinguish a safe repeated read from an uncertain write.
