# DOC-025 — Rollout troubleshooting sequence

When a newly deployed service is reachable but returns `503`, first determine whether endpoints are ready and whether the Service targets the intended Pods. Then inspect the application readiness reason, dependency initialization, and recent configuration changes.

Do not treat a successful TCP connection as proof that a search operation is available. This sequence complements Kubernetes probe guidance: startup handles long bootstrap, readiness controls traffic admission, and Service selectors determine which Pods receive traffic.
