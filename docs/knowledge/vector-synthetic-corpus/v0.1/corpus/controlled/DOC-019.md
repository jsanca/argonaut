# DOC-019 — Message retry and duplicate delivery

At-least-once message delivery can invoke a consumer more than once. Make consumers idempotent by recording a stable message identifier with the completed side effect, or by using an operation that safely overwrites the same state.

Exponential backoff reduces repeated pressure on a failing dependency. A dead-letter queue preserves messages that exceed the retry budget, but it does not make a consumer idempotent and does not change HTTP request semantics.
